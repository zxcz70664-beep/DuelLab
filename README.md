# DuelLab V0.2 在线基础架构

## 当前功能
- 创建6位房间码
- 第二名玩家通过房间码加入；房间满员后拒绝第三人
- 每个席位使用随机令牌进行 WebSocket 身份校验
- 服务端维护双方生命值、回合、阶段、手牌数量和操作日志
- WebSocket 广播房间状态
- 页面刷新后可用当前浏览器 sessionStorage 中的令牌重新连接
- 房间在服务端内存中保存，最多2小时后清理
- /api/health 返回版本和房间数

## 部署
Render 连接 GitHub 分支 v0.2-realtime 后，使用 Dockerfile 构建。Dockerfile 会安装 ws 运行依赖。Render 会提供 PORT 环境变量。

## 两人测试
1. 部署后，玩家1打开网站，点击“创建新房间”。
2. 把6位房间码发给玩家2。
3. 玩家2在另一台设备/浏览器打开同一网站，输入房间码并点击“加入房间”。
4. 两边应显示双人已就绪和相同的生命值、阶段、手牌数、日志。
5. 玩家1点击 +1000 LP，玩家2应看到玩家1生命值同步变化；玩家2操作抽卡，玩家1应看到玩家2手牌数变化。
6. 分别刷新页面，凭证保留在当前浏览器会话中时可点“重新连接”。

## 明确限制
- 这是在线状态同步测试，不是完整决斗。
- 抽卡只同步手牌数量，没有卡组内容或私有手牌数据模型。
- 尚未实现正式卡组、卡牌数据、召唤规则、连锁、效果结算、回合优先权、断线超时判定、数据库持久化、账号系统、TLS 以外的额外身份机制或防作弊裁定。
- 房间保存在进程内存；Render 实例重启、休眠唤醒或重新部署可能导致房间丢失。
- 当前令牌是房间访问凭证，不要公开分享 GitHub 仓库以外的任何秘密（仓库中不应存储用户凭证）。
