# DuelLab 决斗规则复刻实施规范

更新：2026-11-20

## 目标与边界

目标规则：日本 OCG，Master Rule 5（2020 年 4 月规则框架），不是 TCG、Rush Duel、Speed Duel、GOAT 或动画规则。第一阶段为单人本地对战 AI。

规则裁定必须由 Project Ignis / EDOPro 分支的 ocgcore 完成。DuelLab 不在 UI 层自行判断卡片效果是否成立、召唤是否合法、连锁如何处理或战斗结果。当前简化对局保留为 Sandbox，不能标记为 OCG。

## 规则执行架构

1. **OCGCore WASM**：唯一规则裁定来源，处理游戏状态、合法操作、效果、连锁、阶段、战斗和胜负。
2. **CDB Reader**：按卡片密码读取完整 OcgCardData。不能把现有搜索 JSON 的简化字段直接冒充核心数据。
3. **Lua Script Reader**：按核心请求的路径读取与核心版本匹配的 ProjectIgnis/CardScripts；缺失脚本必须报错并阻止该卡进入真实 OCG 对局。
4. **Duel Adapter**：把核心消息和响应转换为 DuelLab 的领域事件/界面操作；不得更改规则语义。
5. **Duel UI**：展示场地、卡片、阶段、连锁、提示、LP 和操作候选；所有操作候选以核心返回为准。
6. **AI Policy**：只在核心等待响应时，从核心提供的合法候选中选择；只能访问己方私有信息与双方公开信息，不得读取对手手牌/牌组顺序。

## 规则覆盖范围（由核心负责）

### 回合与阶段
- 抽卡阶段、准备阶段、主要阶段1、战斗阶段、主要阶段2、结束阶段。
- 回合玩家与非回合玩家的优先权、阶段结束前的响应窗口。
- 首回合抽卡及首回合战斗阶段等规则开关，必须使用所选规则配置，不在 UI 写死。
- 通常召唤/通常盖放次数、表示形式变更、各类特殊召唤及其限制。

### 卡片与区域
- 主卡组、额外卡组、手牌、怪兽区域、魔法陷阱区域、场地区域、灵摆区域、墓地、除外区、超量素材。
- MR5 额外怪兽区域/额外卡组怪兽放置规则。
- 融合、同调、超量、灵摆、连接及仪式等召唤程序；具体合法性由卡片脚本与核心处理。

### 效果与连锁
- 发动条件、时点、费用、对象、取对象与不取对象、效果处理、无效、破坏、离场、重新处理等。
- 连锁构建、连锁顺序、连锁解决、连锁后状态检查与触发效果。
- 卡片文本不能直接作为通用规则解释；具体卡片行为依赖对应 Lua 脚本和 OCG 裁定。

### 战斗
- 攻击宣言、攻击目标、直接攻击、攻击重放。
- 战斗步骤、伤害步骤、伤害计算、战斗破坏、战斗伤害与相关效果时点。
- 攻击次数、攻击限制、战斗阶段退出/进入主要阶段2。

### 胜负与异常
- LP 归零、抽卡失败、特殊胜利/失败条件、平局/同时胜负。
- 脚本错误、缺少卡片数据、缺少脚本、未知核心消息时安全停止，不回退为自制裁定。

## 技术基线（待完成运行验证）

- WASM 包：JSR `@n1xx1/ocgcore-wasm`，截至 2026-11-20 JSR 最新稳定版本为 `0.1.6`。
- 公开 API 包含 `createCore({ sync: true })`、`createDuel`、`startDuel`、`duelProcess`、`duelGetMessage`、`duelSetResponse`、`destroyDuel`。
- 规则模式使用 `OcgDuelMode.MODE_MR5`。
- 创建 Duel 时必须提供 `cardReader` 和 `scriptReader`；核心卡数据至少包括 alias、attack、attribute、code、defense、level、link_marker、lscale、race、rscale、setcodes、type。
- 核心会通过消息请求合法操作/玩家选择；DuelLab 需完整解析并回传对应响应，不可仅监听召唤、攻击等少数消息。
- 当前 JSR 文档说明异步版本依赖 JSPI；先验证目标浏览器。同步版本作为第一轮兼容性 Spike 的候选，不预先承诺所有浏览器均可运行。

## 上游版本锁定策略

不能把“当前最新”作为长期依赖。每次更新必须记录：
- ocgcore-wasm 包版本与完整性校验；
- 该包所包含的 EDOPro ocgcore 源码版本/commit；
- BabelCDB commit；
- CardScripts commit；
- 数据库与脚本的兼容关系；
- 每份资源的许可证及分发义务。

本次调研时看到的上游快照（仅用于调研记录，不代表已下载到 DuelLab）：
- ocgcore-wasm GitHub 仓库：`n1xx1/ocgcore-wasm`，仓库推送时间 2026-11-17。
- CardScripts HEAD：`c6ae1aa29f10f678496064a5e8525ade40286d03`。
- BabelCDB HEAD：`7be9fd135c073d8b9086925853e3cd1cc4ad55ea`。
- 以上两个数据仓库的 HEAD 时间不同；在正式接入前应检查其引用的 core 兼容性，不能仅因日期接近就认定匹配。

## 里程碑与验收

### A. Core Loading Spike
- 固定包版本，核对实际包内 LICENSE、WASM 资源与初始化方式。
- 浏览器页面成功加载 WASM 并读取 core version。
- 提供测试用 cardReader/scriptReader，成功创建 Duel、start、process、读取消息、响应、结束并 destroy。
- 验收：CI 验证构建产物；真实浏览器完成一次最小初始化；失败时展示可诊断错误。
- 未完成前不切换默认决斗入口。

### B. 数据与脚本
- 建立版本锁定的 CDB 与 Lua 脚本资源包。
- 转换完整核心卡片数据，验证所有字段和类型。
- 脚本路径映射可覆盖公共脚本与卡片脚本。
- 对缺失卡片/脚本建立明确报告和阻断策略。
- 抽测通常怪兽、效果怪兽、魔法、陷阱、融合、同调、超量、灵摆、连接、仪式。

### C. 核心消息适配
- 完整支持核心消息解析、状态刷新、玩家选择和响应编码。
- UI 无法表达的响应类型必须阻断，不得跳过或伪造响应。
- 用固定卡组和可重复测试序列核对状态、消息和结果。

### D. 规则回归测试
建立最小测试套件，逐步覆盖：
- 开局、先后手、抽卡与阶段推进；
- 通常召唤、盖放、表示形式变更；
- 特殊召唤及召唤无效；
- 连锁构建、逆序处理、无效与破坏；
- 伤害计算与伤害步骤触发；
- 融合/同调/超量/灵摆/连接召唤；
- 除外、返回手牌/卡组、控制权变更；
- LP 胜负、特殊胜利、抽卡失败；
- 脚本缺失和异常恢复。

### E. AI
- 先解析核心提供的合法操作候选，再做策略排序。
- 逐步实现资源评估、展开、解场、防守、战斗与连锁策略。
- AI 不读取对手隐藏手牌、牌组顺序或未来抽牌。
- AI 选择必须可记录、可复现、可调试。

## 当前状态

- 已有：浏览器工作台、卡牌搜索数据、卡组编辑和本地保存、简化 Sandbox。
- 未有：已集成 WASM 核心、匹配的完整 CDB runtime reader、Lua 脚本资源、核心消息适配器、真实 OCG 决斗、AI。
- 下一项开发：A 阶段加载 Spike。不能以规则文档完成、CI 通过或简化 Sandbox 可运行来宣称已复刻 OCG。
